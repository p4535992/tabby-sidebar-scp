# tabby-sidebar-scp 0.1.2

This release binds the SCP panel to the SSH connection Tabby has already
authenticated and speaks the legacy SCP protocol on it. Release tags and package
versions use plain numeric semantic versions (**`0.1.2`**, never `v0.1.2`).

## Changes since 0.1.1

- The remote pane follows the focused SSH tab, split panes included: listings,
  folder creation, rename/move and recursive upload/download run on that session,
  so Tabby's saved password or key is reused and host, user, port and key no
  longer have to be entered again.
- Transfers use the **legacy SCP protocol** (`scp -t` / `scp -f`) on an exec
  channel of the bound connection: the server needs `scp` but **no SFTP
  subsystem**, and no local `scp`/`ssh` process is started.
- The earlier SFTP backend was removed; the local OpenSSH `scp -O` path remains
  as an explicit fallback used only while no SSH session is open.
- New **Settings → SCP Sidebar** page with an *Enable the SCP file browser*
  switch (`scpSidebar.enabled`): the panel is removed or re-created at runtime,
  without restarting Tabby or unloading the plugin.
- The session bar shows the bound tab; the badge reads `SCP` with a tooltip that
  distinguishes the session path from the local client, and the initial remote
  directory is the shell's reported working directory when available.
- Remote folder favorites are keyed by the bound session's host, user and port.
- The remote move command reports a refused overwrite on stderr, so the session
  path surfaces the same error as the manual path even without an exit status.

## Tests

- `npm test`: 21 unit tests pass (mocked backends, no SSH access).
- `npm run build`: the production bundle contains `dist/index.js`.
- The SCP protocol code was exercised against a simulated remote `scp -t` /
  `scp -f` server: listing, mkdir, move, file and recursive upload, file and
  recursive download, cancellation, progress and stderr-based error propagation.
- The Ubuntu VM GitHub Actions workflow re-runs the unit tests and the Tabby
  renderer smoke tests before publishing this release.

Not covered by automated tests: the settings switch inside a live Tabby window,
manual drag-and-drop, native file pickers, and Windows/macOS compatibility. Test
with disposable files before production use.

## Install from this GitHub release

Download **`tabby-sidebar-scp-0.1.2.tgz`** from the release assets and verify it
with **`SHA256SUMS.txt`**. Close Tabby, install the archive into Tabby's plugin
directory, and restart Tabby completely. See
[installation instructions](https://github.com/p4535992/tabby-sidebar-scp#download-and-install-release-012).

This is a GitHub release; **it does not automatically publish to npm**.

## Requirements and limitations

- Tabby plugin runtime (target: Tabby 1.0.231+) and an open SSH tab for session
  mode.
- Session mode needs the remote `scp` command and a POSIX login shell; listing,
  `mkdir` and `mv` require **GNU `find`** (`-printf`) and `mv --`.
- The exec channel exposes no exit status, so a remote command is treated as
  failed when it writes to stderr.
- Manual fallback mode needs local OpenSSH `ssh` and `scp` with working
  noninteractive authentication and trusted host keys.
- Better Sidebar integration is an optional **DOM compatibility adapter**, not a
  supported upstream API. Changes to Better Sidebar may require updates.
- SCP can overwrite existing files. Confirm paths and test with unimportant data.
